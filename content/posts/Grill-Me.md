# grill-me

> **开篇摘要**：grill-me 通过在编码前进行系统性的访谈式追问，遍历决策树（数据模型、接口设计、异常处理、性能指标、安全策略、回滚方案、测试策略等）直到所有模糊地带被消除，最终生成一份可执行的设计总结。它适合作为任何新功能、重构或技术选型的第一站。

## 一、功能简介

**grill-me** 是 Matt Pocock 技能套件中的核心技能，在写任何代码之前，通过系统性的访谈式追问，彻底澄清需求与设计决策。它会遍历决策树的每一个分支——数据模型、接口设计、异常处理、性能指标、安全策略、回滚方案、测试策略——直到所有模糊地带被消除，生成一份可执行的设计总结。

本质上，它是把“强迫 AI 先思考再行动”这件事标准化、可复用化。适合作为任何新功能、重构或技术选型的第一站。

## 三、部署到 OpenCode

OpenCode 的技能目录通常位于项目根目录的 `.opencode/skills/` 下。将下载好的 `SKILL.md` 放入该目录即可。

```bash
# 在项目根目录下
mkdir -p .opencode/skills
cp SKILL.md .opencode/skills/grill-me.md
```

文件名可以自定，但建议保留 `grill-me` 以便识别。

部署完成后，**重启 OpenCode** 或重新加载技能配置（视 OpenCode 具体机制而定），使新技能生效。

> **前置配置（首次使用）** ：如果在使用 `/grill-me` 前提示缺少仓库配置，请先在 OpenCode 中运行一次 `/setup-matt-pocock-skills`，它会询问 issue 追踪方式、标签约定、文档路径等，后续所有技能将共用这套约定。

## 四、使用方法

### 4.1 基本触发命令

在 OpenCode 对话中输入：

```
/grill-me <你的计划或想法>
```

例如：

```
/grill-me 我想实现一个用户积分系统，根据消费和签到行为累积积分
```

### 4.2 工作流程

1. **系统性遍历决策树**：技能会识别所有关键分支（数据建模、接口契约、异常路径、性能/缓存、安全边界、回滚、监控、测试策略等）
2. **一次只问一个问题**：每个分支聚焦一个具体问题，待你回答后再进入下一个
3. **优先从代码库获取信息**：如果某个答案能从现有代码中推断，它会主动读取相关文件，减少你的重复输入
4. **输出设计总结**：所有分支闭合后，生成一份简洁的总结，包含：
   - 各分支的最终决策
   - 仍存在的假设（明确标记为“待确认”）
   - 推荐的下一步动作（如 `/write-a-prd` 或直接开始实现）

### 4.3 实际会话示例（节选）

输入：

```
/grill-me 做一个房屋租赁系统的AI智能推荐模块，根据用户浏览历史推荐房源
```

可能的追问序列（简化）：

- **Q1**：“推荐算法的实时性要求是秒级（在线推理）还是分钟级（离线批处理）？” → 决定技术选型（Redis + 轻量模型 vs. 定时任务）
- **Q2**：“用户浏览历史的数据源是已有的行为日志表，还是需要新建埋点？” → 决定数据接入方式
- **Q3**：“推荐结果需要分页吗？是否需要排除已下架房源？” → 影响查询过滤逻辑
- **Q4**：“冷启动（新用户无历史）如何处理？是否降级为热门房源？” → 定义兜底策略
- **Q5**：“是否需要记录推荐曝光和点击，用于后续效果评估？” → 决定是否加入埋点

回答完所有问题后，生成的设计总结会清晰列出上述决策，并指出仍未明确的假设（如“假设推荐模型暂时用简单的协同过滤，暂不引入深度学习”）。

## 五、常用场景

| 场景 | 典型用法 |
|------|----------|
| **新功能开发起点** | `/grill-me 我要开发[功能描述]`，先锁定设计边界再动手 |
| **架构重构前评估** | `/grill-me 重构[模块A]为微服务，需要拆表和服务拆分`，推演影响面和回滚策略 |
| **需求模糊澄清** | 当产品文档只有一句话时，用它逼出所有隐含细节 |
| **技术选型决策** | `/grill-me 缓存方案选Redis还是本地Caffeine？`，它会追问并发量、数据一致性要求等 |
| **与其他技能衔接** | 配合同套件的 `write-a-prd` 将访谈结果转为正式文档，或配合 `tdd` 进入红绿重构循环 |

## 六、最佳实践清单

1. **一次设计，长期受益**：grill-me 只提问不写代码，但它生成的设计总结可以作为后续开发的 roadmap，反复查阅
2. **回答尽量具体**：模糊回答（如“差不多就行”）会导致后续假设累积，影响最终质量；可引用已有代码或文档作为依据
3. **善用“我不知道”**：若某个问题暂时无法回答，可说明“需要查XX文档”或“先按默认方案”，技能会记录为待确认假设
4. **与 MAP.md 和 Graphify 配合**：先用 MAP.md 让 agent 建立项目全貌，再用 Graphify 定位代码关系，最后用 grill-me 聚焦新功能的设计——三者形成“总览 → 定位 → 决策”的闭环
5. **定期复盘设计总结**：随着开发推进，若发现原假设不成立，可重新运行 `/grill-me` 更新设计（此时它会以已有代码为上下文，只追问变更部分）

## 七、常见问题

**Q：安装后 OpenCode 无法识别 `/grill-me` 命令？**  
A：检查 skill 文件是否放在正确的技能目录下，并确保重启了 OpenCode。部分版本可能需要手动在配置中声明技能路径。

**Q：grill-me 会直接修改代码吗？**  
A：不会。它纯做访谈，不调用任何代码生成工具，输出仅为 Markdown 格式的设计总结。

**Q：需要每次都完整跑完所有问题吗？**  
A：对于简单改动（如修复单点 Bug），不需要；对于中等以上规模的功能或重构，建议完整走一遍。技能本身会根据你的描述动态调整问题数量。

**Q：如何更新 grill-me 到最新版？**  
A：重新下载仓库中的 `SKILL.md` 并覆盖原文件即可。
