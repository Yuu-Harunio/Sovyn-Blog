# 编程小白的 Hermes Agent 培养手册（从 0 到全栈工程师）

> 基于三元组认知架构（Skill / Fact / Memory），专为"编程零基础 + Obsidian 知识库 + 日常工作辅助"场景定制。

> **开篇摘要**：本手册基于 Skill / Fact / Memory 三元组认知架构，为编程零基础用户规划从"降噪"到"全栈工程师"的六阶段成长路线：搭建 Skill 体系、接入 Obsidian 事实体系、建立 Memory 体系、串联自动化闭环，并给出远期升级图数据库的路线图。

------

## 第零章：先搞懂三个抽屉

在动手之前，你需要理解那位大佬的核心思想。把它想象成**你办公桌上的三个抽屉**：

| 抽屉 | 名称               | 里面放什么               | 生活类比           |
| ---- | ------------------ | ------------------------ | ------------------ |
| 🔧    | **Skill（技能）**  | 怎么做某件事的步骤       | 菜谱、SOP手册      |
| 🗺️    | **Fact（事实）**   | 什么东西和什么东西有关系 | 通讯录、组织架构图 |
| 📝    | **Memory（记忆）** | 发生过什么、聊过什么     | 日记本、会议记录   |

**核心原则（必须刻在脑子里）：**

- Skill 只写"怎么做"，不写"谁的东西"
- Fact 只写"是什么、和谁有关系"，不写"怎么操作"
- Memory 只补充，不推翻前两者

> 你作为编程小白，最大的优势是：**你不需要一开始就搞图数据库和 TEI 部署。** 你的 Obsidian 天然就是一个轻量级的事实图谱（双向链接 = 关系）。我们从最简方案起步，逐步升级。

------

## 阶段一：开箱降噪（第 1 天）

### 目标

把 Hermes 自带的"噪音"关掉，让它变成一张干净的画布。

### 操作步骤

**Step 1：删除默认 Memory 和自动 Skill**

对 Hermes 说：

```
请帮我执行以下初始化操作：
1. 清空当前所有自动生成的 Memory 条目
2. 删除所有自动生成的 Skill
3. 关闭自动记忆写入和自动Skill创建的Hook
4. 操作完成后告诉我你改了什么，我确认后再继续
```

**Step 2：配置事实提取模型**

如果你有 DSv4Flash（DeepSeek-V4-Flash）的 API：

```
请将事实提取/分类的辅助模型配置为 DSv4Flash。
用途：从对话中自动提取关键事实、生成摘要。
不需要它做复杂推理，只做信息提取和格式化。
```

> 💡 **小白提示**：如果你暂时没有 DSv4Flash，用任何便宜的小模型都行，甚至先跳过这步，手动复制粘贴也可以。核心是**别让主模型干提取的脏活**。

**Step 3：验证降噪成功**

随便聊几句，然后问：

```
你现在的Memory里有什么？Skill里有什么？
如果都是空的，说明降噪成功。
```

### ✅ 阶段一完成标志

- Hermes 不再自动往 Memory 里塞东西
- 不再自动创建莫名其妙的 Skill
- 你能看到"干净的三个空抽屉"

## 阶段二：搭建 Skill 体系——你的全栈技能树（第 1~2 周）

### 目标

把你未来要用的所有"做事套路"写成 Skill，让 Hermes 按套路干活，而不是每次瞎编。

### 核心理解

**Skill 不是代码，是"做事的说明书"。**

你不需要会写代码，你只需要会描述"这件事分几步做"。Hermes 会帮你执行。

### 全栈工程师 Skill 树（从小白到进阶）

#### 🌱 第一批：生存级 Skill（第 1 周就建）

**Skill 1：代码解释**

```
名称：explain-code
触发：当用户粘贴一段代码并询问含义时
步骤：
1. 逐行解释代码功能，用非技术语言
2. 画出数据流向（用文字描述：输入→处理→输出）
3. 指出可能的坑和边界情况
4. 给出"如果我要改X，应该改哪里"的指引
输出格式：Markdown，带代码高亮
```

**Skill 2：报错诊断**

```
名称：debug-error
触发：当用户粘贴报错信息时
步骤：
1. 识别报错类型（语法/逻辑/环境/依赖）
2. 用一句话翻译报错含义（说人话）
3. 给出最可能的3个原因，按概率排序
4. 每个原因给出具体修复命令
5. 如果用户是小白，额外给出"为什么会遇到这个错"的科普
```

**Skill 3：项目脚手架**

```
名称：project-init
触发：当用户说"我要新建一个XX项目"时
步骤：
1. 确认技术栈（前端/后端/全栈）
2. 生成目录结构
3. 生成 package.json / requirements.txt 等配置文件
4. 生成 README.md（包含启动命令）
5. 给出"下一步该做什么"的清单
```

**Skill 4：Git 日常操作**

```
名称：git-daily
触发：当用户提到提交、分支、合并、冲突时
步骤：
1. 先确认当前状态（git status）
2. 用中文解释当前状态意味着什么
3. 给出具体命令，每行命令后加注释
4. 警告不可逆操作（如 force push）
```

#### 🌿 第二批：进阶级 Skill（第 2 周）

**Skill 5：API 对接**

```
名称：api-integration
触发：当用户需要调用某个API时
步骤：
1. 确认API文档地址或接口信息
2. 生成请求代码（含错误处理）
3. 生成测试用的curl命令
4. 列出常见坑（鉴权、频率限制、数据格式）
```

**Skill 6：数据库操作**

```
名称：db-operation
触发：当用户需要建表、查询、迁移时
步骤：
1. 确认数据库类型（MySQL/PostgreSQL/SQLite/MongoDB）
2. 生成SQL/ORM代码
3. 解释每个字段的用途
4. 给出备份命令（先备份再操作）
```

**Skill 7：部署上线**

```
名称：deploy
触发：当用户说"部署""上线""发布"时
步骤：
1. 确认目标环境（本地/云服务器/Vercel/Docker）
2. 生成部署脚本
3. 列出检查清单（环境变量、端口、域名）
4. 给出回滚方案
```

### 怎么创建这些 Skill？

直接对 Hermes 说：

```
请帮我创建一个Skill，内容如下：
[粘贴上面的Skill内容]

要求：
- 保存为文本格式
- 不要绑定任何具体项目或IP
- 只描述步骤，不写死具体参数
- 创建后告诉我Skill的调用方式
```

### 日常使用方式

以后你遇到问题，不用从头描述，直接说：

```
使用 debug-error 技能帮我看看这个报错：
[粘贴报错]
```

### ✅ 阶段二完成标志

- 你至少有 5 个常用 Skill
- 遇到重复性问题时，你第一反应是"用哪个 Skill"而不是"重新描述一遍"
- Hermes 的输出格式变得稳定、可预期

## 阶段三：接入 Obsidian——你的事实体系（第 2~4 周）

### 目标

让 Hermes 能**读取和写入**你的 Obsidian 知识库，把散乱的笔记变成结构化事实。

### 为什么 Obsidian 天然适合做 Fact 体系？

| Obsidian 特性    | 对应 Fact 体系概念                 |
| ---------------- | ---------------------------------- |
| ``               | 实体之间的关系（= 图的边）         |
| 文件夹/标签      | 分层级（= 图的层级）               |
| YAML frontmatter | 结构化属性（= 图的节点属性）       |
| 图谱视图         | 可视化关系网（= 图数据库的可视化） |

> 你暂时**不需要**部署 Graphify 或 Neo4j。Obsidian 的 Markdown + 双向链接就是你的"穷人版图数据库"。等你笔记超过 500 条、关系复杂到 Obsidian 图谱看不懂时，再考虑迁移。

### Step 1：规划 Obsidian 文件夹结构

在你的 Obsidian 库中建立以下结构（如果还没有的话）：

```
📁 我的知识库/
├── 📁 00-Inbox/          ← 临时丢进去的东西，待整理
├── 📁 10-Projects/       ← 正在进行的项目（事实：项目相关）
│   ├── 📁 项目A/
│   └── 📁 项目B/
├── 📁 20-Tech/           ← 技术知识（事实：技术栈相关）
│   ├── 📁 前端/
│   ├── 📁 后端/
│   ├── 📁 数据库/
│   └── 📁 运维/
├── 📁 30-Work/           ← 工作相关（事实：业务相关）
│   ├── 📁 公司资产/
│   ├── 📁 流程规范/
│   └── 📁 会议纪要/
├── 📁 40-Skills/         ← 技能笔记（和Hermes Skill对应）
├── 📁 50-Journal/        ← 日记/学习日志（Memory的补充）
└── 📁 99-Templates/      ← 模板
```

### Step 2：定义 Fact 笔记模板

在 `99-Templates/` 里创建一个事实笔记模板：

```markdown
---
type: fact
category:       # 技术/项目/资产/流程
created: {{date}}
updated: {{date}}
tags: []
---

# {{标题}}

## 是什么
（一句话描述这个事物）

## 关系
- 属于：
- 关联：、
- 依赖：

## 关键属性
| 属性 | 值 |
|:---|:---|
| 类型 | |
| 位置 | |
| 状态 | |

## 备注
```

### Step 3：让 Hermes 能读写 Obsidian

**方案 A（最简单）：手动复制粘贴**

每次让 Hermes 整理时，把笔记内容贴给它，让它输出整理后的 Markdown，你再粘回 Obsidian。

**方案 B（推荐）：文件系统接入**

如果你的 Hermes 支持文件系统访问（本地部署或挂载）：

```
请扫描以下目录：/path/to/你的Obsidian库/

规则：
1. 读取所有 .md 文件
2. 识别 frontmatter 中的 type 字段
3. 提取  作为关系
4. 不要修改原始文件，先给我一个整理报告
```

**方案 C（进阶，等你熟悉了再做）：MCP / 插件接入**

搜索是否有 Obsidian MCP Server 或类似插件，让 Hermes 直接通过 API 读写 Obsidian。

### Step 4：让 Hermes 帮你整理已有笔记

对 Hermes 说：

```
我会给你一批我Obsidian里的笔记（可能是乱的、重复的、格式不统一的）。
请你：
1. 去重：内容相同的合并
2. 分类：按我的文件夹结构归类
3. 补链接：如果两篇笔记内容相关，用  连起来
4. 补frontmatter：按我的模板格式补全
5. 输出整理后的Markdown，我手动粘贴回去

不要删除任何信息，只做结构化和关联。
```

### Step 5：日常使用——让 Hermes 带着你的知识库工作

```
我要做 [具体任务]。
请先从我的知识库中查找与 [关键词] 相关的笔记，
结合你的 Skill [技能名]，给我一个方案。

如果知识库里没有相关信息，告诉我，我会补充。
```

### ✅ 阶段三完成标志

- 你的 Obsidian 有了清晰的文件夹结构
- 至少 20 篇笔记被整理成标准 Fact 格式
- Hermes 能在你提问时引用你知识库里的内容
- 你开始习惯"先查库，再干活"

## 阶段四：建立 Memory 体系——别每次都从零开始（第 4~6 周）

### 目标

让 Hermes 记住你们之间的协作历史，形成"越用越懂你"的效果。

### 核心理解

Memory ≠ 聊天记录。Memory 是**从对话中提炼出的、对未来有用的信息**。

### Step 1：定义什么该记、什么不该记

| ✅ 该记                                                | ❌ 不该记                    |
| ----------------------------------------------------- | --------------------------- |
| 你的技术偏好（"我喜欢用 TypeScript 不用 JavaScript"） | 一次性的闲聊                |
| 项目决策（"这个项目选了 SQLite 因为部署简单"）        | 已经被 Skill 覆盖的操作步骤 |
| 踩过的坑（"上次 npm install 失败是因为代理"）         | 已经被 Fact 覆盖的客观信息  |
| 你的工作习惯（"我通常晚上写代码"）                    | 临时性的调试过程            |

### Step 2：创建 Memory 写入 Skill

```
名称：memory-extract
触发：每次长对话结束时（或手动触发）
步骤：
1. 回顾本次对话
2. 提取以下类型的信息：
   - 用户偏好/习惯
   - 项目决策及原因
   - 踩坑记录
   - 未完成的事项
3. 格式化为一条Memory记录
4. 检查是否与已有Memory重复，重复则更新而非新增
5. 标注时间戳和来源对话摘要
```

### Step 3：创建 Memory 召回 Skill

```
名称：memory-recall
触发：每次新对话开始时自动执行
步骤：
1. 获取当前任务关键词
2. 从Memory中检索相关记录（最多5条）
3. 将召回内容作为上下文补充
4. 重要规则：Memory仅作为参考和补充，
   不得覆盖Skill中的操作步骤，
   不得推翻Fact中的客观事实
```

### Step 4：配置自动提取（如果你已配好 DSv4Flash）

```
请在每次对话结束时，自动调用 DSv4Flash 执行以下操作：
1. 判断本次对话是否包含值得记忆的信息
2. 如果有，按 memory-extract 的格式提取
3. 写入Memory存储
4. 不需要我确认，静默执行即可
5. 每周给我一份Memory周报（记了什么、用了什么）
```

### ✅ 阶段四完成标志

- 新对话开始时，Hermes 能说出"上次你提到了XX"
- 你不需要重复解释自己的偏好
- Memory 不会覆盖你的 Skill 和 Fact

## 阶段五：串联与自动化（第 6 周+）

### 目标

把三个抽屉连成流水线，形成 **"做事→记录→积累→做得更好"** 的闭环。

### Step 1：修改 Hook（如果你有能力或 Hermes 支持）

```
请将自动Skill创建的Hook修改为：
每 5 轮对话提醒我一次：
"提醒：你可以使用以下工具：
 1. 🔧 Skill（查技能/创建技能）
 2. 🗺️ Fact（查知识库/添加事实）
 3. 📝 Memory（查历史/记录经验）
请问本次任务需要用到哪些？"
```

> 如果你改不了代码，替代方案：在你的系统提示词里加一句：
> `每5轮对话主动提醒用户检查Skill/Fact/Memory三个工具是否可用。`

### Step 2：建立日常工作流

**场景：接到一个新开发任务**

```
你对Hermes说：

"我要做一个 [任务描述]。请执行以下流程：

1. 📝 Memory召回：查一下我之前有没有做过类似的事
2. 🗺️ Fact查询：从我的Obsidian知识库里找相关的技术笔记
3. 🔧 Skill匹配：确定用哪个Skill来执行
4. 综合以上信息，给我方案
5. 我确认后开始执行
6. 完成后自动Memory提取本次经验"
```

**场景：学习新技术**

```
"我要学习 [技术名]。请：

1. 🗺️ 查我的知识库，看我有没有相关基础笔记
2. 🔧 用 explain-code 技能，从最简单的例子开始
3. 每学完一个知识点，帮我生成一篇Fact笔记
   （按我的Obsidian模板格式，含双向链接）
4. 📝 记录我的学习进度到Memory"
```

**场景：整理 Obsidian**

```
"请帮我做一次知识库整理：

1. 扫描 00-Inbox，把里面的笔记分类到对应文件夹
2. 检查 10-Projects 里有没有已结项的项目，归档
3. 找出所有没有双向链接的"孤儿笔记"，建议关联
4. 检查 20-Tech 里的技术笔记有没有过时的，标记出来
5. 给我一份整理报告，我确认后再执行"
```

### Step 3：每周复盘（强烈建议）

每周花 10 分钟对 Hermes 说：

```
请帮我做本周复盘：
1. 本周使用了哪些Skill？哪些高频？哪些没用过？
2. 本周新增了哪些Fact？有没有需要修正的？
3. 本周Memory里记了什么？有没有可以提炼为新Skill的？
4. 我的Obsidian知识库本周变化如何？
5. 下周建议我重点做什么？
```

## 阶段六：远期升级路线（第 2 个月+）

当你用熟了以上所有内容，再考虑那位大佬的"完全体"方案：

| 升级项                      | 触发条件                            | 做什么                                         |
| --------------------------- | ----------------------------------- | ---------------------------------------------- |
| Obsidian → 图数据库         | 笔记 > 500 条，关系复杂到图谱看不清 | 部署 Graphify 或 Neo4j，把双向链接迁移为图关系 |
| 手动复制 → TEI 向量检索     | 每次找笔记都要翻很久                | 部署 TEI + VectorDB，实现语义搜索              |
| 手动 Memory → 自动提取      | 你总是忘记记录                      | 配好 DSv4Flash 自动提取管线                    |
| 单 Agent → 多 Agent         | 你的任务类型超过 3 种               | 按那位大佬的方式，把工具接入所有 Agent         |
| 纯文本 Skill → 可执行 Skill | 你开始写代码了                      | Skill 里嵌入可执行脚本片段                     |
